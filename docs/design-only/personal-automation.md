# DIY versus SaaS for a personal automation

Status: **design only**. No YAML case is shipped.

## The decision, stated small

A recurring personal task (for example, filing notes or reminding about a bill) can be a script the person runs, or a subscription that runs it for them.

| | Script (build) | Subscription (buy) |
| --- | --- | --- |
| Up-front | An evening of setup | An account and a card |
| Ongoing | The person fixes breakage | The vendor changes the plan |
| Exit | The script stays in the person's files | Export, if it exists, plus the habit of the product's UI |
| Gated effects | The script should not send messages or move money until the person has run it by hand | Paying the subscription is the person's action |

The TCO model in this repo can hold that shape: hours times a personal rate marked [EST], against a seat price marked [EST], plus an exit cost. Until those envelopes are written with a source and a date, this page stays a sketch.

## Approval

The person is the decision owner. There is no second approver in the design.
